# Monitoring integrations

## Implemented today — source and setup

Signs of Life includes adapters for Stripe, Polar, Paddle, RevenueCat, PostHog, Google Analytics 4, Better Auth, WorkOS, Clerk and Auth0 alongside Supabase and App Store Connect. This guide describes source behavior and required setup; [status.md](status.md) records the verified production rollout separately from provider acceptance. Signs of Life operator authentication is unchanged.

Create a project, open Sources, choose a provider and connect its account. Then select an actual account, organization, project, property, app, environment or tenant as a source. Auth providers without application attribution monitor their environment/tenant. Connection validity, selected-resource errors, import progress and live collection are separate. Reconnect keeps the notification baseline and checkpoints; it does not replay historical alerts. Source limits default to 25 per workspace; existing MAX_SOURCES overrides still apply.

## Implemented today — operator OAuth registrations

Set each pair on **both API and jobs**; jobs need the client secret to refresh customer tokens. These are installation credentials, distinct from customer keys stored encrypted in PostgreSQL. Optional registrations enable OAuth buttons; credential fallback remains available without them.

| Provider    | Environment variables                                | Exact callback path on PUBLIC_URL         |
| ----------- | ---------------------------------------------------- | ----------------------------------------- |
| Stripe Apps | STRIPE_OAUTH_CLIENT_ID, STRIPE_OAUTH_CLIENT_SECRET   | /api/monitor/connections/stripe/callback  |
| Polar       | POLAR_OAUTH_CLIENT_ID, POLAR_OAUTH_CLIENT_SECRET     | /api/monitor/connections/polar/callback   |
| PostHog     | POSTHOG_OAUTH_CLIENT_ID, POSTHOG_OAUTH_CLIENT_SECRET | /api/monitor/connections/posthog/callback |
| Google      | GA4_OAUTH_CLIENT_ID, GA4_OAUTH_CLIENT_SECRET         | /api/monitor/connections/ga4/callback     |

For the maintained origin the callback prefix is `https://sol.arminayat.dev`. Register the full URL exactly. Use separate registrations/credentials for isolated testing. PostHog authorization/token endpoints follow the selected region; the registered client must be valid there.

Stripe Apps requires an OAuth app manifest with the read permissions above and allowed redirect URI. Public install links require Stripe publication/review. **STRIPE_OAUTH_CLIENT_SECRET is the app developer's secret API key for the registered live/test install link**, used as HTTP Basic authentication at the token endpoint; it is not a connected customer's key or Stripe Connect secret. Configure the client ID and developer key for the same mode. The returned livemode determines source environment. See [Stripe Apps OAuth](https://docs.stripe.com/stripe-apps/api-authentication/oauth).

Register Polar with the read scopes above. Google must grant offline access for refresh; authorization uses consent and PKCE. OAuth state is single-use, ten-minute, encrypted, workspace/user/project-bound; token refresh uses a lease and compare-and-set so disconnect/rotation wins against a delayed refresh.

## Implemented today — billing webhooks

After connecting Stripe, Polar, Paddle or RevenueCat, open its Webhook dialog in Sources. Copy the displayed `PUBLIC_URL/api/webhooks/monitor/<connection UUID>` endpoint into that provider's dashboard, and save the provider signing secret (RevenueCat: an exact dedicated Authorization header secret) in the dialog. Do not put customer keys in deployment vars.

- Stripe: subscribe to charge.succeeded, invoice.paid, invoice.payment_failed, refund.created, refund.updated and customer.subscription.deleted. A 2024-06-20 webhook version is supported; modern charge events are read back with the pinned API version before classification. Invoice-associated charges share the invoice identity, preventing duplicate payment alerts.
- Polar: order.paid, refund.created/refund.updated, subscription.canceled and subscription.past_due. Standard webhook signatures accept the documented legacy/new Polar signing-key encodings.
- Paddle: transaction.completed, transaction.payment_failed, adjustment.updated and subscription.canceled. Use the endpoint matching the selected production/sandbox environment.
- RevenueCat: initial/non-renewing purchases, renewals, cancellation and billing issues. CUSTOMER_SUPPORT cancellation is a refund, not proof that auto-renewal stopped; its original purchase price is not treated as refund amount. Trial starts do not count as successful payments. BILLING_ERROR cancellation is ignored in favor of BILLING_ISSUE.

Authentication is checked before normalized observations and a processing job are committed atomically. Raw payloads, subscriber profiles, emails, names, addresses and arbitrary metadata are discarded. Signed webhooks enforce a five-minute signature tolerance; repeated events deduplicate through durable identities. Keep provider delivery retries enabled. The API currently bounds incoming request bodies to 128 KB; rejected requests are not accepted/acknowledged as processed.

Stripe references supplied by RevenueCat are candidates only. A same-project connected Stripe account must successfully read the exact object and agree on event kind/environment before matching; provenance remains on each source. Unsupported, ambiguous or inaccessible matches remain separate. A repeated source event is not alerted again when match availability changes. Native MRR, churn, unique users and report totals always remain source-specific. No inferred grand total or identity-by-email exists.

## Implemented today — Better Auth installation

The distributable package is `packages/better-auth-connector`, currently **0.1.0 with Better Auth 1.7.4 explicitly tested**. It is not published to npm. Build/pack locally:

```sh
pnpm --dir packages/better-auth-connector build
pnpm --dir packages/better-auth-connector pack --pack-destination /tmp
```

Install the resulting tarball in the customer application and follow [the connector README](../packages/better-auth-connector/README.md). Add signsOfLife({tokens:[dedicatedToken]}) to existing server plugins, deploy the customer app, then connect its existing auth base URL and token. The plugin adds no tables, writes, Auth hooks or browser instrumentation, and respects Better Auth model/field mappings.

On API and jobs, set `MONITOR_ALLOWED_HOSTS` to a comma-separated exact hostname allowlist. Only public HTTPS port 443 is supported. Requests disallow credentials in URLs and redirects, validate public DNS, and enforce 20-second/4 MB bounds. Node pins the validated address for TLS requests. Cloudflare uses global public fetch, with `global_fetch_strictly_public` enabled and no private-network binding; do not substitute a VPC transport. The allowlist is operator-controlled, never customer-editable.

Probe `GET <auth-base>/signs-of-life/v1/users?limit=1` with the dedicated Bearer token. Rotate by accepting [newToken,oldToken] in the plugin, reconnect with newToken, verify collection, then remove oldToken. Never log tokens or returned account IDs.

## Implemented today — collection, dashboard and retention

Auth polling targets one minute; billing webhook reconciliation targets five minutes; aggregate-only providers and selected dashboard reports refresh hourly. Actual timing depends on queued work and rate limits. Persisted jobs/leases recover restarts, and provider Retry-After defers further requests. Imports use independent opaque cursors and remain silent. Apple reconnect resumes collection; migration 0006 repairs missing daily jobs on previously imported projects.

Overview has Growth, Revenue and Usage sections. Select supported source reports, apply advertised filters, hide/reorder/remove views, and use 7/30/90/365 days or a custom retained range. Exact-value tables accompany charts. Provider definitions, reporting timezone, units/currency, freshness, coverage and unsupported/partial states remain visible. Period unique users and conversion rates come from providers, never daily sums. No arbitrary SQL, formulas, cross-provider funnel or currency conversion is offered.

Signup and successful-payment alerts start enabled; renewals, refunds, cancellations and payment failures are opt-in where supported. Daily summaries include visible selected views once a provider result is available; historical periods remain silent. Existing Apple pending/corrected-report behavior is preserved.

Visible event/delivery history is 30 days. Apple aggregates and minimal observation identities support a 365-day window; unfinished imports/stalled cursors retain dedup identities longer. Normalized event amounts/currency are cleared after 30 days. Native report caches store range/filter results and are invalidated once their range starts outside retention; fresh in-range results are requested from the provider. Daily series points are also retained independently for 365 days. If a provider query fails, retained in-range points can be shown as partial/stale, without a synthesized period total or mixed reporting currencies. Data never previously collected cannot be recreated.
